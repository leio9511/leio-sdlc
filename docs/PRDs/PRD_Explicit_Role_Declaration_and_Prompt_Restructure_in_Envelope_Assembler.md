# PRD: Explicit Role Declaration and Prompt Restructure in Envelope Assembler

## 1. Context & Problem (业务背景与核心痛点)

### Observed Regression
Recent SDLC runs have exhibited agent behavior regression across multiple roles:
- **Coder**: Produced acknowledgment-only output ("I will implement...") without actual code changes. Failed to converge to valid commit checkpoints across multiple rounds.
- **Reviewer**: Produced non-actionable reviews or acknowledgment-only replies instead of evidence-based evaluation.
- **General**: Agents across roles showed loss of role identity, responding as general-purpose assistants rather than specialized SDLC agents.

### Root Cause Analysis
The root cause is in `scripts/envelope_assembler.py`'s `render_envelope_to_prompt` function:

1. **Missing Role Identity Header**: The rendered prompt begins directly with `# EXECUTION CONTRACT`. The agent receives no explicit identity declaration (e.g., "You are the Coder"). Role consciousness is entirely dependent on the agent voluntarily reading the playbook referenced in the `reference_index`.

2. **Prompt Structure Problem**: The current structure is flat and passive:
   ```
   # EXECUTION CONTRACT
   - clause1
   - clause2
   ...
   # REFERENCE INDEX
   {"id": "...", ...}
   # FINAL CHECKLIST
   - item1
   ```
   This structure:
   - Buries critical operating constraints in a long flat list (Lost in the Middle effect)
   - Has no "Call to Action" (CTA) — the prompt ends passively with a checklist
   - Lacks visual hierarchy between identity, constraints, and task definition

3. **No Negative Constraint Prominence**: Boundary rules (e.g., Reviewer's "do not run tests", Coder's "do not git push") are mixed into the middle of `execution_contract` clauses, easily overlooked by the LLM.

### Why This Matters
This is a **P0** priority issue because:
- It directly impacts the reliability of the entire multi-agent SDLC pipeline
- It has demonstrably caused at least one full-run crash (forensic archive + PR split)
- The fix is surgical (single-function change in `render_envelope_to_prompt`) with well-defined boundaries

## 2. Requirements & User Stories (需求定义)

### Functional Requirements

**FR-1: Role Prologue Injection**
The `render_envelope_to_prompt` function MUST prepend an `IDENTITY & PRIMARY GOAL` section containing the role's prologue extracted verbatim from the corresponding playbook, covering ALL six agent roles: planner, coder, reviewer, verifier, auditor, forensic.

**FR-2: Structured Prompt Layout**
The rendered prompt MUST follow a hierarchical structure:
1. IDENTITY & PRIMARY GOAL (role prologue)
2. OPERATING CONSTRAINTS (boundary rules, reference-read mandate)
3. EXECUTION CONTRACT (unchanged from current, all clauses preserved)
4. REFERENCE INDEX (unchanged from current)
5. FINAL CHECKLIST (unchanged from current)
6. START WORK (action-oriented CTA)

**FR-3: Role-Specific Boundary Rules**
For reviewer and verifier roles, the EVALUATION_ROLE_BOUNDARY_RULES (e.g., "Do not run repository tests") MUST be lifted from the `execution_contract` middle into the `OPERATING CONSTRAINTS` section for prominence.

**FR-4: No Content Loss**
All existing `execution_contract` clauses, `reference_index` entries, and `final_checklist` items MUST be preserved exactly as generated by the current `_build_*_envelope` functions. Only the prompt structure changes; the content generators are unchanged.

**FR-5: Action-Oriented CTA**
The prompt MUST end with a `START WORK` section containing a directive like `"As the {ROLE}, begin your task now. Read the reference files first, then proceed."` to trigger active execution rather than passive acknowledgment.

**FR-6: Role Prologue Source**
The role prologues MUST be hardcoded in `scripts/envelope_assembler.py` as a `ROLE_PROLOGUES` dictionary, sourced verbatim from the existing playbook files. This ensures:
- No hallucination or drift from playbook language
- Single source of role definition (playbook = reference, hardcoded copy = prompt injection)

### Non-Functional Requirements
- **NFR-1**: The change must not alter the output of `save_envelope_artifacts` (debug_dir structure, startup_packet.json, rendered_prompt.txt).
- **NFR-2**: The change must not require any modifications to playbook files.
- **NFR-3**: The change must not break `build_startup_envelope` or any `_build_*_envelope` function signatures.

## 3. Architecture & Technical Strategy (架构设计与技术路线)

### Target File
- **`scripts/envelope_assembler.py`**: The sole file to be modified. Only `render_envelope_to_prompt` will be restructured; a `ROLE_PROLOGUES` dictionary will be added.

### Design Decisions
1. **Prologues are hardcoded, not dynamically read**: Reading playbook files at runtime would add I/O complexity and potential race conditions. The prologues are stable strings that change only when playbooks change — and in that case, the PRD for the playbook change should include updating the hardcoded copy.

2. **Minimum viable prompt structure**: `IDENTITY → CONSTRAINTS → CONTRACT → REFERENCES → CHECKLIST → CTA`. This is a standard, battle-tested LLM prompt architecture that maximizes instruction following.

3. **Role-specific boundary rules are lifted, not duplicated**: For reviewer/verifier, the `EVALUATION_ROLE_BOUNDARY_RULES` list already exists. We move its rendering position from inside `execution_contract` to inside `OPERATING CONSTRAINTS` without changing the source list.

4. **Forensic agent is included even if not currently in `build_startup_envelope` switch**: Prologue is defined for future-proofing.

### Prompt Structure (Before → After)

**Before:**
```
# EXECUTION CONTRACT
- clause1
- clause2
- ... (boundary rules buried here)
# REFERENCE INDEX
[...]
# FINAL CHECKLIST
- item1
- item2
```

**After:**
```
## IDENTITY & PRIMARY GOAL
You are an autonomous, highly skilled "Fat Coder". You implement features and fix bugs based on the functional requirements provided in the PR Contract.

## OPERATING CONSTRAINTS
- You MUST use the read tool to read every reference in the REFERENCE INDEX where required=true and priority=1 before acting.
- DO NOT git push.
- DO NOT change git branches.
- DO NOT merge into master.

## EXECUTION CONTRACT
- Locked Working Directory: `...`
- Branch isolation rule: ...
- ...
- Before coding, you MUST use the read tool to read every reference...
- Validation rule: ...
- Completion rule: ...
- Reporting rule: ...

## REFERENCE INDEX
[... unchanged ...]

## FINAL CHECKLIST
- Read every required priority-1 reference before making code changes.
- ...

## START WORK
As the CODER, begin your task now. Read the reference files first, then proceed with implementation.
```

## 5. Overall Test Strategy & Quality Goal (测试策略与质量目标)

### Core Quality Risk
The primary risk is **content loss** — accidentally dropping or modifying an existing `execution_contract` clause, `reference_index` entry, or `final_checklist` item during the refactor.

### Test Strategy
1. **Unit Test (primary)**: Write a pytest test in `tests/test_envelope_assembler.py` that:
   - Builds envelopes for all six roles using `build_startup_envelope`
   - Calls `render_envelope_to_prompt` on each
   - Asserts the presence of the IDENTITY, OPERATING CONSTRAINTS, START WORK sections
   - Asserts every original `execution_contract` clause is a substring of the rendered output
   - Asserts every `reference_index` entry's JSON representation appears in the output
   - Asserts the START WORK CTA is the last section

2. **Integration Validation**: Run `./preflight.sh` to ensure existing test suites still pass.

3. **Live Smoke Test**: After deployment, manually trigger a single-PR SDLC run with a trivial PRD to observe agent behavior improvement.

### No Mocking Required
- The test directly calls `build_startup_envelope` and `render_envelope_to_prompt` with test fixtures — no external services or agents are needed.
